# T2: BASS audio backend

Task: T2   Status: **done in code, not built for Android, not tested on a device** (no NDK/SDK here)

## Needs your decision (2 items)

1. **The Java never compensated for output latency (bug), so the port defaults to "off".**
   `BassAudio.getOutputLatencyMs()` polls with `now - lastLatencyPoll >= 1000` where `lastLatencyPoll` starts at `Long.MIN_VALUE`.
   `now - Long.MIN_VALUE` overflows to a negative number, so the condition is never true, the poll never runs and the
   method always returned 0 (confirmed by running the expression on a real JVM). `COMPENSATE_DEVICE_LATENCY = true` was therefore inert.
   I kept the real behaviour (0 ms) so timing and saved offsets do not shift. To get what the Java comments intended
   (poll `BASS_INFO.latency` once a second, subtract `latency * rate` from the position while playing) call
   `opsu::bass::BassAudio::setPollOutputLatency(true)` once at startup. It logs `Output latency: X ms` when the value changes.
   Turning it on moves every note by the device latency, so re-check the global offset if you do.
2. **`setLowPass` (muffle) is not in the uploaded `BassMusic.java`.** AbsMusic's default was a no-op there. I implemented it
   from the AGENT_TASKS.md spec (details below). If a newer Java file has it, send it and I will diff.

## What is ported exactly (same BASS calls, flags, order)

- Init: `UPDATEPERIOD 5`, `BUFFER 100`, `DEV_BUFFER 10`, then `BASS_Init(-1, 44100, 0)`; `BASS_ERROR_ALREADY` is accepted.
- Music: `BASS_STREAM_PRESCAN | BASS_STREAM_DECODE` by file name (`BASS_FILE_NAME`), fallback to memory (`BASS_FILE_MEM`, buffer kept alive
  as long as the stream); `BASS_FX_TempoCreate(src, BASS_FX_FREESOURCE)`; `BASS_SYNC_END`; `ended` flag restarts at 0 on the next
  `play()/loop()`; `stop()` = pause (keeps position); `setPitch` = `BASS_ATTRIB_TEMPO (r-1)*100` with `MIN_RATE 0.05` (`PRESERVE_PITCH = true`);
  `getPosition` = bytes -> seconds, minus `latency/1000*rate` only while `BASS_ACTIVE_PLAYING` (see decision 1);
  `getLevels` = `BASS_ChannelGetLevelEx(1/60 s, BASS_LEVEL_STEREO)`; `getFFT` = `BASS_DATA_FFT512` -> 256 floats (out is untouched on failure).
  Error messages for `java::IOException` are the Java strings.
- Clips: `BASS_SampleLoad(.., max 32, BASS_SAMPLE_OVER_POS)`, `BASS_SAMCHAN_NEW` per play, volume clamped to [0, 1], loop via
  `BASS_ChannelFlags(LOOP)`, `setChannelFrequency` remembers the sample's ORIGINAL rate per channel and clamps to [100, 100000] Hz.
  Missing file, empty file (intentional silence) or load failure -> silent clip (`play` returns 0), never null.
- Stream clip: `BASS_StreamCreateURL(url, 0, 0, null, null)`, volume, `BASS_SYNC_END`, play; stream opened on every `play()`.
- Muffle (spec): `setLowPass(hz)`: `hz >= 20000` (or NaN) removes the effect. Otherwise a BASS_FX biquad
  (`BASS_FX_BFX_BQF`, `BASS_BFX_BQF_LOWPASS`, `fQ = 0.7071`, `fBandwidth = 0`, `lChannel = BASS_BFX_CHANALL`) is created ONCE with
  `BASS_ChannelSetFX` and afterwards only `BASS_FXSetParameters` is called, and not even that when the (clamped) cutoff did not change.
  Cutoff is clamped to [1 Hz, Nyquist-1].

## Threading (important for you)

BASS sync callbacks run on BASS's thread. They never run game logic: they set a flag and queue an event.
**You must call `opsu::bass::BassAudio::pumpEvents()` once per frame on the game thread**, otherwise `onComplete` (music ended) and the
stream-clip `onEnd` never fire. Alternative: `BassAudio::setEventPoster(fn)` to push events into your own game-thread queue
(`fn` is called on BASS's thread, so it must be thread-safe). Events whose owner was disposed or destroyed in the meantime are dropped
safely; an `onComplete` handler may dispose its own music.

## Differences from Java / the T1 contract (small)

- `BassClip::play()` ignores `onEnd`, exactly like Java (`BassClip` ignored its listener). T1's header says `onEnd` fires for any clip.
  Only `BassStreamClip` reports the end of playback, and, like Java, only at the natural end, not on `stop()`/`destroy()`/replay.
  If T1's `SoundController` needs `onEnd` from sample clips, tell me.
- File lookup: Java used `ResourceLoader` (registered locations). The core has no equivalent, so: a plain file on disk is used first;
  otherwise, on Android, a RELATIVE path is looked up in the APK assets (e.g. `res/theme.mp3`) via `BassAudio::setAssetManager(...)`.
  If you add a resource-location seam to the core, `BassAudio::readResource()` is the one place to change.
- `BassAudio::init()` returns false + logs instead of throwing (Java threw `IllegalStateException`). After a failed init `createMusic`
  throws `java::IOException`, clips/stream clips are silent.
- Tiny hardening: NaN volume -> 0; `BassClip::stop()` also forgets remembered channel base rates; a stream clip can be played again after `destroy()`.
- `volFade`/`pitchFade`: Java `BassMusic` did not override them, so T1's defaults (pause / no-op) apply.
- Optional `BassAudio::setJavaVM(vm)` (`BASS_CONFIG_ANDROID_JAVAVM`, set before `BASS_Init`). The Java build got the VM through
  `System.loadLibrary`; this app has `hasCode=false`. I could not read `bass.chm` here, so I only know the option exists from `bass.h`.
  Try it (`app->activity->vm`) only if non-mp3/ogg/wav formats fail on a device.
- `BASS_StreamCreateURL` blocks the calling thread while connecting (as in Java).

## Debug entry point ("done when": plays `theme.mp3`)

I may not edit `main.cpp`/CMake, so the hook is a function you call from `android_main` (one line, plus the include):

```cpp
#include "platform/audio/BassBackend.h"
// in android_main(android_app* app), before the loop:
static std::unique_ptr<opsu::AbsMusic> g_music = opsu::bass::debugPlayAsset(app->activity->assetManager);
// inside the loop, once per frame:
opsu::bass::BassAudio::pumpEvents();
```

It sets the asset manager, inits BASS, creates a `BassMusic` for `res/theme.mp3` (read from `assets/`), volume 0.5, looped.
Optional while testing: `BassAudio::setPollOutputLatency(true);` before it.

## How to build and test on a device

1. Merge T1's three headers into `core/include/opsu/audio/` (if not already), copy my files into the tree, add the snippet above.
2. `./gradlew assembleDebug` (both ABIs). If it fails, send me the compiler/linker error.
3. `adb install -r app/build/outputs/apk/debug/*.apk`, start it, `adb logcat -s opsu BassAudio BassMusic BassClip BassStreamClip BassDebug`.
   Expected: `[BassAudio] BASS initialised (BASS_FX ...)`, `[BassMusic] Loaded res/theme.mp3`, `[BassDebug] playing res/theme.mp3`, and the theme is audible and loops.
4. Things I could not check and you should (a temporary test call is enough):
   - `music->setPitch(1.5f)` raises speed without raising pitch; `setPitch(0.75f)` slows it; `getPosition()` runs at the track rate.
   - Muffle: call `music->setLowPass(1000.f)` each frame, then sweep up and call `setLowPass(20000.f)`. Listen for a click when the effect
     is created or removed, and check `fBandwidth = 0` really makes BASS_FX use `fQ = 0.7071` (if the sound looks wrong, try `fBandwidth` ≈ 1.9 octaves instead, which is the same as Q 0.7071).
   - Set `onComplete` and play a short file with `play()`: it must fire once (needs `pumpEvents()`).
   - A hit-sound clip from a real file, `playLoop` + `setChannelFrequency` (slider slide / spinner).
   - Preview clip from a URL (INTERNET permission is already in the manifest).
   - Both ABIs (arm64-v8a and armeabi-v7a).
