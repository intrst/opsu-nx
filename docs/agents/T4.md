## Decisions agreed with the project owner (Java kept as written)
- `inputLocked` blocks only `touchDown`, `scrolled`, `keyDown`, `keyTyped` (like the Java). `touchUp`, `touchDragged`,
  `touchCancelled`, `keyUp` always pass, so a finger or key that went down before a skin swap is still released.
- **Known Java quirk, kept:** there is ONE shared `rawTarget` field, written on every raw finger-down. If the state changes while
  finger A is down and finger B goes down on the new raw state, A's move/up/cancel now go to the new listener
  (test `testSingleRawTargetQuirk`).
- Cancel of a RAW finger clears only that pointer's owner (not `rawTarget`), other raw fingers are unaffected.

## Other deviations from the Java
- Every handler is wrapped in try/catch + `Log::error` (also `catch (...)`). The Java only wraps `touchDown` and the raw paths.
- In `touchUp`/`touchDragged` the "released" state (`rightIsPressed`, `oldx/oldy`) is updated even if a target throws.
- **Java behaviour worth knowing (kept):** a cancelled MENU finger is handled as `touchUp`, so a quick cancelled touch (< 500 ms,
  < 10 px) still produces `mouseClicked` + `mouseReleased`.
- `AndroidInput` cancels all fingers when the surface size or game resolution changes (rotation) and on `cancelAll()`.
  `CANCEL` cancels the highest slot first, so the emulated right button is released before the "mouse".
- A DOWN for an Android id that is already active (lost UP) first cancels the old slot, then goes down again.
- The 21st simultaneous finger gets no slot and is ignored (its UP is ignored too). Events return 1 for it.

## WIP / not done
- Global input listeners (Java `GInputListener` list with `consumeEvent`, `addInputListener`): not ported. `scrolled` therefore only
  calls the target (the Java would also give global listeners `-amountY * 120`).
- `mouseMoved` (desktop only, never produced by touch) is not ported. The Java one passes `screenX` twice as `newy`; port it as a bug-for-bug
  copy or fix it when a desktop backend exists.
- `keyTyped` / text input: `AInputEvent` has no unicode char (needs JNI or an IME). `keyPressed` always gets `char 0`, like the Java.
  The router's `keyTyped` only reports the lock.
- Mouse buttons from an OTG mouse (right/middle): every `ACTION_DOWN` is sent as LEFT. Mouse hover (`HOVER_MOVE`) returns 0 (ignored).
  Mouse wheel works (`ACTION_SCROLL`).
- Stylus/gamepad/sensor events are not handled (return 0).
- Android `onInputEvent` is the native_app_glue form; for GameActivity only `readMotionEvent` / the key reading in `onInputEvent`
  (`AndroidInput.cpp`) must be replaced, `handleMotion` / `handleKey` / `MotionSample` stay.

## Key mappings (`AndroidInput::mapKeycode`: AKEYCODE -> libGDX `Input.Keys`)
Unmapped keys return 0 from the event handler, so the system keeps them (volume, home, power ...). Mapped keys return 1.
libGDX copies the Android numbers; verified: ESCAPE/END/INSERT/F1..F12 match Android since libGDX 1.9.13 (the Java needs >= 1.12).
The only translated key is Ctrl.

| Android | libGDX | | Android | libGDX |
|---|---|---|---|---|
| BACK | 4 (`Keys.BACK` = `Input.ANDROID_BACK` = `Input.KEY_BACK`) | | F1..F12 | 131..142 |
| MENU | 82 (`ANDROID_MENU`) | | SHIFT_LEFT / RIGHT | 59 / 60 |
| ESCAPE | 111 | | **CTRL_LEFT / RIGHT (113 / 114)** | **129 / 130** |
| ENTER | 66 | | ALT_LEFT / RIGHT | 57 / 58 |
| NUMPAD_ENTER | 160 | | GRAVE | 68 |
| SPACE / TAB | 62 / 61 | | MINUS / EQUALS / PLUS | 69 / 70 / 81 |
| DEL (backspace) | 67 (`Keys.DEL`, Java `KEY_DELETE`) | | COMMA / PERIOD / SLASH | 55 / 56 / 76 |
| FORWARD_DEL | 112 | | SEMICOLON / APOSTROPHE | 74 / 75 |
| DPAD_UP/DOWN/LEFT/RIGHT | 19 / 20 / 21 / 22 | | BACKSLASH / [ / ] | 73 / 71 / 72 |
| PAGE_UP / PAGE_DOWN / MOVE_END | 92 / 93 / 123 | | 0..9 | 7..16 |
| A..Z | 29..54 (= `Keys.h`) | | NUMPAD_0..9 | 144..153 |

Confirm: Ctrl 129/130 is libGDX's documented constant (libGDX issue #7189 says Android sends 113/114, a proposed libGDX change to
113/114 may exist in a newer release). Whoever extends `core/include/opsu/input/Keys.h` must use the same numbers.
BACK/ESC: `Input.isBackButton` accepts `ANDROID_BACK` (4) or `KEY_ESCAPE` (111); both reach the state.
Java oddity to settle when the menu states are ported: in `fake/Input.java` `KEY_BACK == ANDROID_BACK == 4`, while `SongMenu`,
`DownloadsMenu` and `TextField` use `KEY_BACK` as the backspace key (in Slick it was 0x0E). Android DEL arrives as 67.
Key repeats are forwarded as repeated key downs (text fields need them). Pointer slots: no libGDX translation needed (slots are only an index).
Mouse wheel: `ACTION_SCROLL` -> `scrolled(-sign(h), -sign(v))` (libGDX does the same), so wheel up = `mouseWheelMoved(+1)`.

```cpp
#include <android/native_window.h>
#include "opsu/input/TouchRouter.h"
#include "platform/input/AndroidInput.h"

namespace {
// Logs every menu-side event: check with `adb logcat -s opsu`.  Replace with the real state later.
struct LogTarget : opsu::InputTarget {
    void mousePressed(int b, int x, int y) override { __android_log_print(ANDROID_LOG_INFO, "opsu", "press b=%d x=%d y=%d", b, x, y); }
    void mouseReleased(int b, int x, int y) override { __android_log_print(ANDROID_LOG_INFO, "opsu", "release b=%d x=%d y=%d", b, x, y); }
    void mouseClicked(int b, int x, int y, int n) override { __android_log_print(ANDROID_LOG_INFO, "opsu", "click b=%d x=%d y=%d n=%d", b, x, y, n); }
    void mouseDragged(int ox, int oy, int nx, int ny) override { __android_log_print(ANDROID_LOG_INFO, "opsu", "drag %d,%d -> %d,%d", ox, oy, nx, ny); }
    void mouseWheelMoved(int a) override { __android_log_print(ANDROID_LOG_INFO, "opsu", "wheel %d", a); }
    void keyPressed(int k, char) override { __android_log_print(ANDROID_LOG_INFO, "opsu", "key down %d", k); }
    void keyReleased(int k, char) override { __android_log_print(ANDROID_LOG_INFO, "opsu", "key up %d", k); }
} g_logTarget;
opsu::AndroidInput* g_input = nullptr;

void onAppCmd(android_app* app, int32_t cmd) {
    switch (cmd) {
        case APP_CMD_INIT_WINDOW:
        case APP_CMD_WINDOW_RESIZED:
        case APP_CMD_CONFIG_CHANGED:
            if (g_input && app->window)
                g_input->setSurfaceSize(ANativeWindow_getWidth(app->window), ANativeWindow_getHeight(app->window));
            break;
        case APP_CMD_LOST_FOCUS:
        case APP_CMD_TERM_WINDOW:
        case APP_CMD_PAUSE:
            if (g_input) g_input->cancelAll();   // no stuck fingers
            break;
    }
}
}  // namespace

// in android_main(), before the loop:
opsu::TouchRouter router([] { return &g_logTarget; });   // later: return the current game state
opsu::AndroidInput input(router);
g_input = &input;
app->userData = &input;
app->onInputEvent = &opsu::AndroidInput::onAppInputEvent;
app->onAppCmd = onAppCmd;
// ... and when the game switches screen:  router.onStateEntered();
```
(`app->userData` and `app->onAppCmd` are unused in the current `main.cpp`; if another task has taken them, chain instead.)
`android_native_app_glue` delivers input on the main thread inside `src->process(...)` of the existing poll loop, so no extra thread handling.

## Device checklist
1. One finger tap: logcat shows `press` -> `click` -> `release` (left, same x/y). A long press (> 0.5 s) or a swipe: no `click`.
2. Drag one finger: `drag old -> new` lines, only while it moves.
3. Hold finger 1, tap finger 2: `press b=1` at finger 1's LAST position (not finger 2's), lift: `click b=1` + `release b=1`. Finger 1 keeps dragging.
4. Lift finger 1 first while finger 2 is down, then finger 2: no stuck button, new finger lands on slot 0 and acts as the mouse again.
5. Rotate the phone with a finger down: the finger is released (no stuck finger, no events afterwards). Surface size in the log/`setSurfaceSize` is the new one.
6. Pull the notification shade or use an edge gesture mid-touch (ACTION_CANCEL): fingers are released; note a quick cancel logs click+release (Java behaviour).
7. Home, recent apps and lock: fingers released (`cancelAll` on LOST_FOCUS / PAUSE).
8. BACK button/gesture: `key down 4` / `key up 4` and the app does NOT close. Volume keys still change the system volume.
9. Bluetooth/OTG keyboard: letters, digits, arrows, F-keys, Esc (111), backspace (67), Ctrl (129/130), held key repeats.
10. OTG mouse wheel: `wheel +1` for wheel up, `-1` for down.
11. Gameplay (once a raw state exists): 3+ fingers each keep their own cursor; cancelling one finger leaves the others; state change while down keeps events on the original listener.
